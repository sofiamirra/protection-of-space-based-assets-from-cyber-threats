# Cybersecurity and National Defence - Technical Project

## Topic B - Cyber Risk Prioritization and Treatment Tool

## Project Overview

This repository contains the technical implementation and source code developed as the practical component associated with the academic report on **Cybersecurity and National Defence**.

The project implements a simple **Cyber Risk Prioritization and Treatment Tool** designed to analyze cyber threat scenarios, estimate their risk level, evaluate existing security controls, and recommend additional mitigation measures when necessary.

The technical implementation is intended to complement the analysis presented in the associated PDF report.

---

## Risk Assessment Model

The program reads three JSON input files containing:

- assets;
- threat scenarios;
- security controls.

For each threat scenario, the initial risk is calculated as:

```text
Risk = Likelihood × Impact
```

The program then applies the reductions provided by the security controls already deployed in the scenario and calculates the **residual risk**.

The residual risk is compared with the acceptable risk threshold defined for the affected asset.

If the residual risk is higher than the acceptable threshold, the tool recommends additional security controls from the available catalog.

A control can be recommended only if:

- it is applicable to the threat associated with the scenario;
- it is not already deployed.

The example dataset is based on **space-related cyber-physical assets**, including:

- GNSS Ground Stations;
- AOCS Sensors;
- SpaceWire buses;
- COTS hardware;
- TT&C uplink channels.

## How to Run

Run the program from the project root directory.

### Windows

```bash
python main.py --input input --output output/result.json
```

### macOS / Linux

```bash
python3 main.py --input input --output output/result.json
```

The `--input` argument must point to the directory containing the input JSON files.

The `--output` argument specifies the path of the JSON file generated by the program.

If the output file already exists, it is overwritten.

## Input Files

The example `input` directory contains:

```text
input/
├── assets.json
├── security_controls.json
└── scenarios.json
```

### `assets.json`

Contains the assets to be protected.

Each asset includes:

- `id`
- `name`
- `type`
- `value`
- `criticality`
- `risk_threshold`

### `security_controls.json`

Contains the catalog of available security controls.

Each control includes:

- `id`
- `name`
- `description`
- `applicable_threats`
- `likelihood_reduction`
- `impact_reduction`

### `scenarios.json`

Contains the cyber threat scenarios to be analyzed.

Each scenario includes:

- `id`
- `asset_id`
- `threat`
- `exposure`
- `likelihood`
- `impact`
- `deployed_controls`

In the example dataset, most scenarios initially have no deployed controls.

Scenario `S4` already includes one deployed security control, allowing the implementation to demonstrate how residual risk is calculated when a mitigation measure is already in place.

## Main Data Structures

The implementation uses Python dictionaries for the main lookup operations.

Assets are indexed by their identifier:

```python
assets_dict = {a["id"]: a for a in assets.get("assets", [])}
```

This allows the program to efficiently retrieve an asset using its `id`.

Security controls are indexed in the same way:

```python
controls_dict = {
    c["id"]: c
    for c in controls.get("security_controls", [])
}
```

This allows the program to efficiently retrieve a security control from its identifier.

Threat scenarios are stored as a list and processed sequentially.

---

## Risk Treatment Logic

For each scenario, the program performs the following steps:

1. retrieves the associated asset;
2. calculates the initial risk;
3. applies the reductions provided by deployed controls;
4. calculates the residual risk;
5. compares the residual risk with the asset's acceptable threshold;
6. recommends additional controls when necessary;
7. calculates the projected risk after the recommended controls;
8. assigns a treatment result;
9. sorts the final results according to priority.

The recommendation strategy follows a **greedy approach**.

Applicable controls are ordered according to:

```text
likelihood_reduction + impact_reduction
```

Controls are then added progressively until:

- the acceptable risk threshold is reached; or
- no additional applicable controls are available.

---

## Output

The program generates a JSON output file containing two main sections:

- `summary`
- `risk_results`

The `summary` section provides an overview of the analysis.

The `risk_results` section contains one result for each processed threat scenario.

Each scenario result includes information such as:

- initial risk;
- deployed controls;
- residual risk;
- acceptable threshold;
- scenario status;
- recommended controls;
- projected risk after recommendation;
- treatment result;
- priority.

Possible treatment results are:

- `already_acceptable`
- `threshold_met`
- `threshold_not_met`

## Edge Case Handling

The implementation explicitly handles unknown security control identifiers.

If a scenario contains a control ID that is not present in `security_controls.json`, the program does not terminate.

Instead, the unknown reference is reported in the output under:

```json
"invalid_control_references": []
```

The scenario is still processed using all valid controls.

The implementation also prevents the same deployed control from being counted more than once if its identifier appears multiple times in the input data.

---

## Design Limitations

The main limitation of the implementation is the **greedy recommendation strategy**.

This approach is intentionally simple and transparent, but it does not guarantee the optimal combination of security controls for larger or more complex datasets.

In addition, the risk model uses simplified integer scores for likelihood and impact. This is appropriate for the scope of the project, but a real-world cyber risk assessment would require a more detailed evaluation of technical, operational, organizational, and contextual factors.
